## 2. E2 bf16 消口径列：本机不可行落账，弃全量列（2026-09-30 作者拍板）

预注册预算 ~1-2h GPU；实测**物理 CPU 墙 0.77 tokens/s**（4bit ~20 tok/s 的 1/26），条均
190-310s，4 格 280 条 ≈ **15-24h**，超预算 10 倍以上。三轮诊断实录（证据
`output/med-e/e2-smoke*.log`）：

| 轮 | 配置 | 结果 |
|---|---|---|
| 1 | 整装上卡（默认） | `caching_allocator_warmup` 即 OOM（要 14.27GiB，常驻外空闲 10.99GiB） |
| 2 | `--device_map auto` 裸开 | 加载过但 CPU 侧层留 mmap 页（进程 RSS 仅 530MB）+ 系统 swap 7/7 满 → 每前向缺页风暴（GPU 0%/线程全闲/224s/条） |
| 3 | + `--max_memory {0: 9GiB, cpu: 40GiB}`（**int 键**，JSON 串键被 accelerate 拒） | 物理落地：GPU 驻 7.7GB（~28% 层）+ CPU 14/16 核算满（~72% 层）→ 190s/条稳态，load 14.5/16、GPU 0%——瓶颈为 CPU 算力，软件无空间 |

**工具路径终态已验通**：评测器 bf16 分支补 `--device_map auto --max_memory`（加载机制
修补，判分口径零改动）；mini2 冒烟两条判分全绿（fmt ✓ / F1 1.0 / cov 1.0 / 幻觉 0，
`output/med-e/f1-bf16-val-reg.mini2.jsonl`）——后续在 ≥32GB 显存单卡上分钟级可补全量。

**决策**（2026-09-30，作者四选一拍板）：弃全量列落账走人。地图读数脚注维持"4bit 口径"
并注记升级路径；E2 时段转 E3/E4，波次按 D-08 计划收官。

（61 处引用全部 train 零出现），0.133 是零命名先验下的纯模式泛化读数。

### 3.2 泛化存在性判决（判据：依据覆盖轴 unseen 侧 > 零样本，同集对照）

零样本 test-ood 覆盖 **0.927** 为基线：f1 0.969 / f2 0.972 / cg 0.974 / cm 0.965 / cn 0.964 /
cn-low 0.985 / dpo-s1 0.969 / dpo-s3 **0.974** / dpo-s9 0.974——**10/11 配方过线，判据成立**
（唯 f3c 0.893 破线，与其 MED-B 出局原因覆盖破线一致）。**泛化推理存在性 = 成立**：在零
命名先验下，微调模型的证据组织能力（轴③）迁移超过零样本——泛化兑现集中在覆盖轴，
不在命名轴（轴①），两轴分叉是结构性的。

### 3.3 侧读数正式落卷：unseen 命名/证据分叉（预跑复核逐 id 一致）
